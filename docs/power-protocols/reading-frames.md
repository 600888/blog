# 报文阅读与分析方法

看到一串十六进制数据时，先不要急着换算业务值。先确定它属于哪条连接、哪个方向，以及是否包含完整的应用报文。

## 先保留原始上下文

记录时间、发送方向、设备角色、连接标识与原始字节。只保留解析后的值，会丢失定位解析错误需要的证据。

```text
时间       2026-01-01 10:00:00.000
方向       主站 → 设备
传输       TCP / 串口（填写实际类型）
原始字节   按接收顺序记录
解析结论   完整帧 / 不完整帧 / 待确认
```

以上是日志格式示例，不是一帧真实规约报文。

## 分三层阅读

| 层次 | 需要确认的内容 |
| --- | --- |
| 边界与结构 | 起始标识、长度、控制字段、结束或校验字段（若规约包含） |
| 数据编码 | 字节序、符号、BCD 或浮点编码、时间格式 |
| 业务映射 | 地址对应的测点、单位、倍率、质量与状态 |

不要把某一规约的帧结构直接套到另一规约上。先根据正式格式划分字段，再解释每个字段。

## 字节序与数值

以无符号 16 位整数为例，字节 `01 02` 按大端解释为 `0x0102 = 258`，按小端解释为 `0x0201 = 513`。

这个例子只说明字节序的影响。真实数据还可能涉及字交换、编码偏移、符号、倍率或其他规约约定。

## 带着交互序列判断

请求、确认、响应、超时和重试应放在时间线上观察。一个字段在单帧里看似正确，也可能与当前交互状态不匹配。

## 形成可复现记录

保留原始报文、字段偏移、解析结果、预期值和判断依据。下一次出现同类问题时，可以直接对照，而不是重新猜测。
