# 1838. 最高频元素的频数

[力扣原题（完整题面）](https://leetcode.cn/problems/frequency-of-the-most-frequent-element/description/)

### 题意

给定数组 `nums` 和整数 `k`，最多进行 `k` 次“选一个元素加 `1`”操作，求操作后某个值能达到的最大出现次数。

### 样例 1

```text
输入：nums = [1,2,4], k = 5
输出：3
```

解释：把 `1` 加到 `4` 需 `3` 次，把 `2` 加到 `4` 需 `2` 次。

### 解题思路

操作只能"加 1"不能"减 1"，所以最终的目标值一定是数组中已存在的某个元素，且要把一段较小的元素全部抬升到某个较大的值。

先**排序**。排序后，把窗口 `[l, r]` 内所有元素抬升到 `nums[r]`（窗口内最大的值）所需的操作次数为：

```text
cost = (r - l + 1) * nums[r] - sum(nums[l..r])
```

几何直观：排序后把元素画成一组递增的柱子，`cost` 就是这些柱子与虚线 `x = nums[r]` 之间的空隙面积——也就是蓝色区域。预算 `k` 限制的就是这块面积的大小：

![1838 滑动窗口示意图：蓝色区域为把 [left, right] 内元素抬升到 x 的总操作数](./images/1838-window.png)

于是问题变成「求 cost 不超过 `k` 的最长窗口」，还是 [1004. 最大连续 1 的个数 III](/algorithms/sliding-window/longest/budget/1004) 那套"预算内求最长窗口"模板，只是预算消耗从"异类个数 / 消耗之和"换成了上面这个面积公式：

- 右指针 `r` 扩张，`sum += nums[r]` 维护窗口和；
- 当 `(r - l + 1) * nums[r] - sum > k` 时不合法，左指针 `l` 右移收缩，`sum -= nums[l]`；
- 每轮合法后用 `r - l + 1` 更新答案。

为什么窗口右端点固定用 `nums[r]` 做目标值？排序后对以 `r` 结尾的窗口，抬到 `nums[r]` 是最省钱的选择（抬到更高的值只会更贵）；而更优的目标值如果来自更右的位置，会在后续的 `r` 中被枚举到，不会遗漏。

### 我的代码

```cpp
class Solution {
public:
    int maxFrequency(vector<int>& nums, int k) {
        sort(nums.begin(), nums.end());
        int l = 0, r = 0;
        long long sum = 0;
        int ans = 0;
        for (r = 0; r < nums.size(); ++r) {
            sum += nums[r];
            while ((long long)(r - l + 1) * nums[r] - sum > k) {
                sum -= nums[l];
                l++;
            }
            ans = max(ans, r - l + 1);
        }
        return ans;
    }
};
```

时间复杂度 `O(n log n)`：排序占主导，窗口部分 `l`、`r` 各最多前进 `n` 次，均摊 `O(n)`。空间复杂度 `O(log n)`：排序的栈开销，窗口本身只用常数个变量。

一个关键细节是**溢出**：`(r - l + 1) * nums[r]` 是"窗口长度 × 最大值"，`n` 和元素值都可能到 10^5 量级，乘积可达 10^10，超出 `int` 范围，所以要像代码里那样显式转成 `long long` 再参与比较；`sum` 也同步用 `long long` 维护。

另外一个思考方向：`cost` 具有单调性——窗口右移时 `cost` 不减、左移收缩时 `cost` 不增，这保证了 `while` 收缩的正确性，也说明本题可以二分窗口长度（额外用前缀和 + 二分，`O(n log n)`），但滑动窗口写法常数更小、代码更短。
