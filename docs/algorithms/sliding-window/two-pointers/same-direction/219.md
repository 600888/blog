# 219. 存在重复元素 II

[力扣原题（完整题面）](https://leetcode.cn/problems/contains-duplicate-ii/description/)

### 题意

给定整数数组 `nums` 和整数 `k`，判断是否存在两个不同下标 `i`、`j`，使 `nums[i] = nums[j]` 且下标距离不超过 `k`。

### 样例 1

```text
输入：nums = [1,2,3,1], k = 3
输出：true
```

解释：下标 `0` 和 `3` 的元素相同，距离为 `3`。

### 样例 2

```text
输入：nums = [1,2,3,1], k = 1
输出：false
```

解释：唯一的重复元素对距离为 `3`，超过 `k = 1`。

### 解题思路

把「存在距离不超过 `k` 的重复元素」换个说法：**求数组中重复元素之间的最小下标距离，判断它是否不超过 `k`**。这就不再是判断布尔值，而是求最小值，于是可以用「不定长滑动窗口（求最小）」的套路：

- 右指针 `r` 一直向右扩张，用哈希表 `cnt` 维护窗口 `[l, r]` 内各元素的出现次数；
- 如果 `cnt[nums[r]] > 1`，说明窗口里已经存在另一个 `nums[r]`，此时 `[l, r]` 本身就是一对合法的重复元素，用 `r - l` 更新最小距离；然后左指针 `l` 右移收缩，直到 `cnt[nums[r]]` 降为 `1`；
- 循环结束后 `ans` 就是全数组的最小重复距离，`ans <= k` 即为答案（`ans` 未被更新说明没有重复，保持 `INT_MAX`，自然返回 `false`）。

为什么收缩是安全的、不会漏掉最优解？关键在于**收缩终止的位置**：`while` 循环退出时，`l` 恰好停在窗口内最后一个 `nums[r]` 的下标 `p` 的后一位，也就是循环最后一轮记录的 `r - p` 正是「以 `r` 为右端点的最近重复距离」。前面几轮记录的 `r - l` 只会更大，取 `min` 后自然被覆盖掉。

### 我的代码

```cpp
class Solution {
public:
    bool containsNearbyDuplicate(vector<int>& nums, int k) {
        int l = 0, r = 0, n = nums.size();
        unordered_map<int, int> cnt;
        int ans = INT_MAX;
        for (r = 0; r < n; ++r) {
            cnt[nums[r]]++;
            while (cnt[nums[r]] > 1) {
                ans = min(ans, r - l);  // 满足条件的情况下取最小
                cnt[nums[l]]--;
                l++;
            }
        }
        return ans <= k;
    }
};
```

时间复杂度 `O(n)`：`l` 和 `r` 各最多前进 `n` 次。空间复杂度 `O(min(n, |Σ|))`：哈希表只存窗口内出现过的元素。

三个细节：

- **`ans = min(ans, r - l)` 写在收缩循环内，且必须在 `l++` 之前**：这一轮记录的是「当前窗口左端到 `r` 的距离」。循环中段会移除一些与 `nums[r]` 无关的元素（例如窗口 `[5,1,1]` 在 `r = 2` 时先移除 `5`），这些轮次记下的是偏大的虚假距离，但它们不会污染答案——循环最后一轮记下的才是真实最近距离，且必然不大于前面任何一轮；
- **不需要 `erase` 零计数键**：与 3 题不同，本题的判断条件是 `cnt[nums[r]] > 1`，只看单个元素的计数，计数减到 `0` 的键留在表里不影响任何判断；
- **用 `INT_MAX` 兜住「无重复」的情况**：没有任何重复时 `ans` 保持初始值，`INT_MAX <= k` 天然为 `false`，不必额外写特判分支。

### 与其他写法的对比

本题还有一种更直接的哈希写法：只记录每个值**上一次出现的下标**，不维护窗口。

```cpp
class Solution {
public:
    bool containsNearbyDuplicate(vector<int>& nums, int k) {
        unordered_map<int, int> last;
        for (int r = 0; r < nums.size(); ++r) {
            auto it = last.find(nums[r]);
            if (it != last.end() && r - it->second <= k) return true;
            last[nums[r]] = r;
        }
        return false;
    }
};
```

两种写法的取舍：

| 写法 | 思路 | 特点 |
| --- | --- | --- |
| 收缩窗口（本篇代码） | 维护 `[l, r]` 的频次，收缩到无重复 | 通用模板，与 3、2958 题同构；先求最小距离再比较 `k` |
| 上一次出现位置 | 只记 `last[nums[r]]`，判断 `r - last <= k` | 更快更短，能提前 `return true`，但看不出滑动窗口结构 |

用滑动窗口的版本更好迁移：把「`cnt[nums[r]] > 1`」换成别的局部约束，就能直接改写 220 题（存在重复元素 III）；而 `last` 写法则只适用于本题这一种「相等 + 距离」判定。

顺带说明本题与 220 题的边界：220 要求「值差不超过 `valueDiff`」而不是「完全相等」，窗口内无法只靠一个计数键判断是否重复，需要用**定长桶**（宽度 `w = valueDiff + 1`，同桶即冲突）或**有序集合**做窗口最值维护——这正是[滑动窗口与数据结构](../../advanced/239.md)那一类要处理的问题。
