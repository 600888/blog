# 1052. 爱生气的书店老板

[力扣原题（完整题面）](https://leetcode.cn/problems/grumpy-bookstore-owner/description/)

### 题意

给定每分钟的顾客数 `customers` 和老板是否生气的数组 `grumpy`。老板可选择连续 `minutes` 分钟不生气；求最终满意顾客的最大人数。

### 样例 1

```text
输入：customers = [1,0,1,2,1,1,7,5], grumpy = [0,1,0,1,0,1,0,1], minutes = 3
输出：16
```

解释：选择合适的连续三分钟使用技巧，最多让 `16` 位顾客满意。

### 样例 2

```text
输入：customers = [1], grumpy = [0], minutes = 1
输出：1
```

解释：老板不生气，这位顾客本来就满意。

### 解题思路

把顾客分成两类：

- **原本就满意的**：老板不生气（`grumpy[i] == 0`）的那些分钟，无论用不用技巧，顾客都满意；
- **只有用了技巧才满意的**：老板生气（`grumpy[i] == 1`），且该分钟恰好落在技巧覆盖的区间内。

技巧是**连续 `minutes` 分钟**的定长区间，所以问题变成：选一个长度为 `minutes` 的窗口 `W`，最大化

```
原本满意的顾客总数 - 窗口内原本满意的顾客数 + 窗口内所有顾客数
```

即窗口内的"本来满意"被替换成了"全部满意"，窗口外保持原样。

于是需要两样东西：

1. **前缀和 `preSum`**：`preSum[i]` 表示 `[0, i]` 中原本满意（`grumpy == 0`）的顾客数。注意 `preSum[0]` 也要判断 `grumpy[0]`，不能直接赋 `customers[0]`。
2. **定长窗口**：维护窗口内**所有**顾客之和 `sum`（因为窗口内技巧全覆盖，生气的也被救回来了）。

枚举每个窗口 `[l, r-1]`（长度恰好 `minutes`）：

- 左侧 `[0, l-1]` 原本满意的人数 = `l == 0 ? 0 : preSum[l-1]`；
- 右侧 `[r, n-1]` 原本满意的人数 = `preSum[n-1] - (r == 0 ? 0 : preSum[r-1])`，当窗口顶到末尾时右侧为空；
- 候选答案 = 左 + 右 + 窗口总和，取最大值。

写法与 2379 相同：右指针先把窗口凑满 `minutes`，结算后左端滑出一个元素（`sum -= customers[l]`），下一轮右端再补入。

### 我的代码

```cpp
class Solution {
public:
    int maxSatisfied(vector<int>& customers, vector<int>& grumpy, int minutes) {
        int n = customers.size();
        // preSum[i]: [0, i] 中「原本就满意」(grumpy==0) 的顾客数
        // 注意：preSum[0] 必须判断 grumpy[0]
        vector<int> preSum(n, 0);
        preSum[0] = (grumpy[0] == 0 ? customers[0] : 0);
        for (int i = 1; i < n; ++i) {
            preSum[i] = preSum[i - 1] + (grumpy[i] == 0 ? customers[i] : 0);
        }
        int ans = 0;
        int sum = 0;  // 窗口 [l, r-1] 内所有顾客之和（超能力全覆盖）
        int l = 0, r = 0;
        while (r < n) {
            // 窗口扩到长度 minutes（或到数组末尾）
            while (r - l < minutes && r < n) {
                sum += customers[r];
                r++;
            }
            // 窗口是 [l, r-1]，所以
            //   左侧原本满意 = [0, l-1] = (l == 0 ? 0 : preSum[l-1])
            //   右侧原本满意 = [r, n-1] = preSum[n-1] - (r == 0 ? 0 : preSum[r-1])
            int left = (l == 0) ? 0 : preSum[l - 1];
            int right = preSum[n - 1] - (r == 0 ? 0 : preSum[r - 1]);
            ans = max(ans, left + right + sum);
            // 左端滑出
            sum -= customers[l];
            l++;
        }
        return ans;
    }
};
```

时间复杂度 `O(n)`：前缀和一遍、窗口滑动一遍。空间复杂度 `O(n)`，用于前缀和数组。

两个易错点：

- `preSum[0]` 必须按 `grumpy[0]` 判断，直接写成 `preSum[0] = customers[0]` 会把老板生气的第一分钟也算成满意；
- 结算时窗口是左闭右开的 `[l, r-1]`，右侧区间从 `r` 开始，对应的前缀和下标要相应处理 `r == 0` 的边界（虽然本题窗口非空、`r >= minutes >= 1`，防御性判断更稳）。

另一种更省空间的写法：先累加所有 `grumpy == 0` 的顾客作为基数，再用窗口只统计**窗口内 `grumpy == 1` 的顾客数**，答案 = 基数 + 窗口内能救回的最大值。思路等价，可以省掉前缀和数组。
